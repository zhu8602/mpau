# mpau 发布台 · 系统优势与业务逻辑

> 版本:v0.1.3。本文描述系统的设计优势与端到端业务流转,可作为对外介绍、团队培训与商业沟通的底稿。

---

## 一、系统定位

**一次创作,全网分发。** mpau 发布台是一个本地部署的多平台内容自动发布系统:覆盖抖音、快手、视频号、小红书、拼多多、天猫/淘宝、京东、百家号、TikTok、B站 10 个主流社交与电商平台。账号扫码登录一次,之后的单条与批量发布——视频、图文、定时、挂商品——全部由系统按平台规则自动完成。

系统的核心命题:**人做创意和审阅,机器做重复和跑腿。**

---

## 二、系统优势

### 1. 效率优势:批量引擎把"人天"压缩到"分钟"

- 标准批量流水线:**导入 → 填标题 → AI 生成 → 矩阵审阅 → 批准 → 限速发布 → 导出报告**,几十上百条视频一次投向多平台、多账号;
- 同一视频按「平台 × 账号」自动展开条目,一次操作覆盖整个账号矩阵;
- 发布后自动生成 CSV 报告,成功/失败/原因逐条留档,可复盘、可重试。

### 2. AI 差异化文案:拒绝"一键同文"

- 只需写一条人工标题,AI 按各平台风格、字数限制生成差异化标题/描述/标签/商品短标题;
- 支持多候选切换、单条重生成、合规校验(极限词检查);
- 接入任意 OpenAI 兼容接口(推荐 DeepSeek),Key 只存本机,按量自付,无中间商加价;不配 Key 时发布等全部其他功能照常可用。

### 3. 内置风控体系:把账号安全做成默认值

| 机制 | 默认值 | 作用 |
| --- | --- | --- |
| 账号串行 + 并发上限 | 并发 4 | 同一「平台+账号」同时只发一条,避免单账号并发触发风控 |
| 条间间隔 | 5 分钟 | 拟人节奏,可调 |
| 每账号日上限 | 25 条 | 超出自动排队,防止单日过量 |
| 防重发 | sha256 指纹 | 同一视频+平台+账号不会重复发布 |
| 试跑演练 | 抖音/拼多多/天猫/京东 | 自动填好全部字段但不点发布,先核对再正式上线 |

### 4. 工程体验:面向"非技术用户"的交付设计

- **安装版零环境**:双击 exe 免管理员安装,Python 运行时与浏览器内核全部内置,不依赖用户电脑装没装 Python/Chrome;
- **内置浏览器打开界面**:管理界面用系统自带的 Chromium 以独立窗口打开,与用户默认浏览器无关,不会出现"打不开/要令牌"的环境问题;
- **托盘常驻**:关闭窗口后系统在托盘待命,右键即可打开主界面或退出,像正常软件一样;
- **数据目录独立**:账号 Cookie、批次、配置保存在 `%LOCALAPPDATA%\mpau-data`,覆盖安装、升级不丢数据;
- **细节体验**:登录后自动抓取平台真实昵称显示;同平台多账号一键全选/取消;主界面默认最大化。

### 5. 安全与合规:数据不出本机

- 账号 Cookie、LLM Key、任务数据全部明文保存在本机,不上传任何云端;
- 后台默认仅监听 `127.0.0.1` 且启用令牌认证;局域网共享模式同样要求持令牌访问,严禁暴露公网;
- 发布动作全部模拟人工浏览器操作,遵守各平台交互路径。

### 6. 可集成性:既能人用,也能被 AI 驱动

- 完整 CLI(`mpau <平台> <动作>`),网页后台的全部能力均可脚本化;
- `skills/` 目录内置各平台技能文档,外部 AI Agent(Kimi Code、Claude Code 等)读取后即可调用 CLI 完成登录检查与发布,适合接入更大的自动化工作流。

### 7. 成本优势

- 本地运行,无 SaaS 订阅费;唯一变动成本是 LLM 调用(用户自配 Key、按量计费、每条约几分钱量级);
- 一台普通 Windows 电脑即可支撑多平台账号矩阵的日常发布。

## 三、业务逻辑

### 1. 核心实体与关系

```
账号(别名 + Cookie + 平台昵称)          素材(视频/图文, sha256 指纹)
        │                                    │
        └──────────┬─────────────────────────┘
                   ▼
        批次 Batch(一次发布战役)
                   │ 按「平台 × 账号」展开
                   ▼
        条目 Item(视频 × 平台 × 账号,最小发布单元)
                   │ 提交
                   ▼
        任务 Task(登录/发布执行记录, 日志留痕)
```

- **账号**:用户扫码登录产生,Cookie 持久化在 `cookies/`;别名是主键,平台真实昵称登录后自动回填展示;
- **素材**:视频以 sha256 做指纹,是防重发的依据;
- **批次**:一组素材 + 一组平台账号映射 + 风控参数构成的一次发布计划;
- **条目**:调度的最小单元,商品 ID、文案、状态都挂在条目级,互不影响;
- **任务**:所有登录/发布动作的执行载体,实时日志,重启后可恢复。

### 2. 账号生命周期

```
扫码登录(有头弹浏览器/无头显示二维码)
   → Cookie 落盘 → 登录任务成功
   → 后台自动抓取平台昵称并回填
   → 日常 check 校验登录态
   → 掉线则重新扫码(历史数据不受影响)
```

### 3. 批量发布主流程(核心业务流)

```
① 导入     扫描文件夹 / 导入 CSV / 选择单条视频
② 填标题   每条视频一条人工标题(AI 生成的基础, 决定文案质量)
③ AI 生成  按「视频 × 平台 × 账号」展开条目, LLM 生成差异化文案
           (未配置 LLM Key 则此步报错, 可改手动填写, 不影响后续)
④ 审阅批准  矩阵逐条核对/修改/批准; 商品 ID 在此逐条设置(只作用本条)
⑤ 限速发布  调度器按风控参数执行: 同账号串行、并发上限、条间间隔、日上限
⑥ 报告     导出批次 CSV, 成功/失败/原因逐条留档, 失败可重试
```

关键设计:**只有「已批准」的条目才能进入发布队列**——AI 负责生产,人负责把关,机器负责执行。

### 4. 条目状态机

```
待生成 → 已生成 → 待审阅 → 已批准 → 发布中 → 成功
                                    ├→ 失败(可重试)
                                    ├→ 跳过(指纹重复/超日限)
                                    ├→ 需人工(如抖音短信验证, 网页内提交验证码后续跑)
                                    └→ 已中断(服务重启, 重新批准可续传)
```

### 5. 调度与风控逻辑

- **串行维度**:同一「平台+账号」任意时刻只执行一条,拟人操作节奏;
- **并发维度**:不同平台/账号之间可并行,全局并发上限默认 4;
- **节奏维度**:同一账号相邻两条之间强制间隔(默认 5 分钟);
- **总量维度**:每账号每日上限(默认 25 条),超出自动顺延排队;
- **去重维度**:视频 sha256 + 平台 + 账号三元组指纹,重复提交自动跳过(可 --force 强制)。

### 6. 商品挂载(挂车)逻辑

- **口径分平台**:抖音=商品链接;视频号/拼多多/天猫/京东=商品 ID(橱窗/商品库搜索挂载);快手=商品名称(小店搜索挂载);
- **颗粒度到条目**:商品 ID/名称在条目编辑里逐条设置,只作用于「该视频 × 该平台 × 该账号」这一条,复制/确定后互不影响——同一条视频发不同账号可以挂不同商品。

### 7. 系统架构

```
用户 ──► mpau-launcher.exe(启动器)
           │ 拉起/复用
           ▼
   Web 服务(Flask, 127.0.0.1:8898, 令牌认证)
           │                ▲
   ┌───────┴───────┐        │
   ▼               ▼        │
 Vue3 网页后台      CLI(mpau_cli)
   │               │
   └───────┬───────┘
           ▼
   pipeline(批量引擎: 扫描/规划/生成/审阅/调度/报告)
           │ 按平台分发子进程
           ▼
   uploader(patchright 浏览器自动化, 10 平台)
           ▼
   各平台创作者后台(模拟人工操作完成发布)
```

- **进程模型**:Web 服务为常驻进程(pythonw, 托盘管理);登录/发布以独立子进程执行,互不阻塞;
- **浏览器内核**:统一使用 patchright 驱动的 Chromium(反指纹检测),安装包内置,与用户浏览器隔离;
- **数据存储**:任务/批次/条目存 SQLite(`data/mpau.db`),配置存 `data/config.json`,凭据存 `cookies/`,昵称元数据存 `data/accounts.json`,日志按平台分文件存 `logs/`。

## 四、典型应用场景

| 场景 | 用法 |
| --- | --- |
| 电商带货矩阵 | 一条商品视频 → 挂不同商品 ID → 分发抖音/视频号/拼多多/天猫/京东多账号 |
| MCN/店群运营 | 几十条素材批量导入 → AI 差异化文案 → 人审 → 限速日更,多账号分摊风险 |
| 内容工作室 | 同一创作全网分发,一次登录长期免登,报告留档复盘 |
| AI 自动化团队 | 以 CLI + Agent Skills 作为发布层,接入自有内容生产流水线 |

## 五、一句话总结

**mpau 把"多平台发布"这件高频、重复、易踩风控的事,封装成一条「人审文案、机器跑腿」的本地流水线:批量提效、AI 提质、风控保命、数据私有。**
